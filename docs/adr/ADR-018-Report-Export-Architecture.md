# ADR-018 — Report Export Architecture

**Status:** Accepted

**Date:** 2026-07-25

**Sprint:** Sprint 10 – Enterprise Reporting

**Decision Makers:** Project Architecture Board

---

# Context

AnalystGPT Enterprise produces multiple analytical outputs throughout the data processing pipeline, including:

- Executive Summary
- Quality Report
- Analytics Report
- Structured Report
- KPI Summary
- Pipeline Execution Summary

These reports represent business artefacts generated by the Reporting Module.

With the introduction of the Streamlit frontend during Sprint 10, users required the ability to request report exports through the graphical interface while maintaining the project's layered architecture.

A report export mechanism was therefore required that:

- Preserved Clean Architecture.
- Avoided business logic inside the frontend.
- Supported multiple export formats.
- Allowed future asynchronous processing.
- Supported both REST API and future React frontend integration.

---

# Problem Statement

If the Streamlit frontend generated reports directly:

- Business logic would move into the Presentation Layer.
- Report generation would be duplicated.
- Export behaviour would differ across interfaces.
- Future API and React integration would become inconsistent.
- Testing would become significantly more difficult.

Report generation therefore required a single orchestration point.

---

# Decision

All report export requests shall be coordinated through the **Reporting Orchestrator**.

The frontend shall only initiate export requests.

The Reporting Orchestrator shall coordinate report generation through the Reporting Module.

No frontend component shall generate reports directly.

# Responsibilities

## Streamlit Frontend

Responsibilities:

- Display available reports.
- Submit export requests.
- Display export status.
- Display success or failure messages.

The frontend shall never:

- Build reports.
- Format reports.
- Write files.
- Access the filesystem directly.

---

## Report Service

Responsibilities:

- Receive export requests from views.
- Forward requests to the Application Layer.
- Transform backend responses into presentation-friendly objects.
- Handle frontend-specific exceptions.

---

## Reporting Orchestrator

Responsibilities:

- Validate export requests.
- Coordinate report generation.
- Route requests to the Reporting Manager.
- Maintain a stable interface for both Streamlit and REST API clients.

The Orchestrator contains no formatting logic.

---

## Reporting Manager

Responsibilities:

- Generate report content.
- Assemble report sections.
- Produce structured reporting data.
- Invoke exporters.

---

## Exporters

Each exporter is responsible for writing exactly one output format.

Examples include:

- Text Report Exporter
- PDF Report Exporter
- HTML Report Exporter
- Markdown Report Exporter
- DOCX Report Exporter

Each exporter remains independent.

# Design Principles

The export architecture follows the following engineering principles.

## Single Responsibility Principle

Each exporter generates only one file format.

---

## Open/Closed Principle

New export formats may be introduced without modifying existing exporters.

Example:

```
CSV Exporter

↓

Excel Exporter

↓

PowerPoint Exporter
```

---

## Dependency Inversion

Frontend depends upon service interfaces rather than reporting implementations.

---

## High Cohesion

Report generation remains entirely within the Reporting Module.

---

## Loose Coupling

Frontend remains independent of:

- Export implementation
- File writing
- Formatting logic
- Report construction

---

# Error Handling

Export failures shall be propagated through the Application Layer.

The frontend shall display user-friendly status messages.

Examples:

```
Export completed successfully.

```

or

```
Export request could not be completed.

```

Internal exceptions shall remain hidden from end users while being logged by the backend.

# Consequences

## Advantages

- Centralised report generation.
- Single export pipeline.
- Consistent behaviour.
- Easier testing.
- Simplified maintenance.
- Enterprise scalability.
- Backend independence.
- React compatibility.

---

## Trade-offs

- Additional orchestration layer.
- Slightly more implementation complexity.
- More interfaces to maintain.

These trade-offs are acceptable because they significantly improve maintainability and scalability.

---

# Alternatives Considered

## Option 1 — Generate Reports Inside Streamlit

Rejected.

Reason:

- Violates Clean Architecture.
- Business logic enters the Presentation Layer.
- Poor maintainability.

---

## Option 2 — Views Calling Reporting Manager Directly

Rejected.

Reason:

- Removes orchestration.
- Increases coupling.
- Makes REST API reuse more difficult.

---

## Option 3 — Multiple Independent Export Pipelines

Rejected.

Reason:

- Duplicate code.
- Inconsistent behaviour.
- Difficult testing.

# Sprint 14 Planned Export Reliability & Ownership Evolution

In Sprint 14, report exports are extended with:
- **Authenticated Ownership Scoping**: Export endpoints strictly enforce authenticated tenant checks (`user_id`), preventing cross-user unauthorized report downloads (IDOR defense).
- **Export Idempotency**: Repeated export requests for the same report run return stable artifacts without disk corruption or duplicate database records.
- **Direct Streaming & File Integrity**: Direct file streaming contracts for text and PDF exports ensuring valid binary payloads across REST API and frontend clients.

# Decision Summary

AnalystGPT Enterprise adopts a centralised Report Export Architecture in which:

- All export requests originate from the frontend.
- Frontend services forward requests to the Application Layer.
- The Reporting Orchestrator coordinates report generation.
- The Reporting Manager constructs report content.
- Dedicated exporters generate output files.

This architecture preserves Clean Architecture principles, eliminates duplication, supports multiple export formats, and provides a stable foundation for future REST API, React frontend, scheduled reporting, and AI-generated reporting capabilities.
