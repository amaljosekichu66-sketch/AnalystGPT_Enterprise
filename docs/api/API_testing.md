# AnalystGPT Enterprise API Testing Guide

> **Purpose**
>
> This document explains how to validate and test the
> AnalystGPT Enterprise REST API.
>
> It covers local execution, Swagger UI, OpenAPI validation,
> automated testing, security validation, and endpoint verification.
>
> Current Version: latest tag **v14.0.0** (released 2026-09-28); **v14.1.0** (pre-Sprint-15
> hardening) is being released. Reconciled with the code on 2026-10-14.

---

# API Testing Overview

The REST API is tested through multiple validation layers to ensure
correctness, reliability, and security.

Testing includes:

- Automated endpoint testing
- Authentication & JWT token verification
- Role-Based Access Control (RBAC) & 401/403 authorization checks
- Server-side IDOR prevention and data isolation checks
- Request & Response validation
- OpenAPI & Swagger UI validation
- Integration testing
- End-to-end pipeline execution
- Live API verification

---

# Prerequisites

Before testing, ensure the following are installed:

- Python 3.11+
- FastAPI & Uvicorn
- Pytest & HTTPX

Install project dependencies:

```bash
pip install -r requirements-dev.txt
```

---

# Starting the API

Run the development server (the first line once: `.env.example` is a production template whose
`CHANGE_ME` signing key the API refuses):

```bash
cp .env.development.example .env
python -m uvicorn src.api.server:app --reload
```

Expected output:

```text
INFO:     Uvicorn running on http://127.0.0.1:8000
```

# Automated Test Execution

### Run All API and Security Tests

```bash
PYTHONPATH=. pytest tests/api/ tests/identity/ -v
```

### Run Frontend Authentication Tests

```bash
PYTHONPATH=. pytest tests/frontend/test_frontend_auth.py -v
```

### Run Full Repository Test Suite

```bash
pytest -q
```

The default suite collects **1,242 tests** (measured 2026-10-14 on `pre-sprint-15-hardening`).
`pyproject.toml` sets `addopts = -ra -m "not integration"`, so the 16 `integration`-marked
tests are deselected and the suite is deterministic on any machine. CI runs it as
`pytest tests/ -v --cov --cov-report=term` with a coverage gate of `fail_under = 85`.

`tests/integration/test_pipeline.py` drives the API the way the frontend does, against a real
database: register (VIEWER), admin promotion, upload, analysis, policy proposal and approval,
pipeline, every dashboard/Power BI view, lineage, text and PDF export, the AI job, cross-user
denial and dataset deletion. `tests/api/test_openapi_contract.py` diffs the committed
`docs/api/openapi.json` against the live schema.

### Run the live-infrastructure tests

```bash
pytest -m integration
```

Without a PostgreSQL test database this selects 16 tests (1,258 collected, 1,242 deselected);
with `TEST_POSTGRES_*` set it adds the 6 PostgreSQL tests:

- `tests/ai/test_ollama_connection.py` (7), `tests/ai/test_ollama_production_path.py` (8),
  `tests/integration/test_live_ollama_pipeline.py` (1) — need a live Ollama server with
  `gemma3:4b`. A recorded run against the synthetic `sample_data/support_tickets.xlsx`
  (generated by `scripts/make_live_sample.py`) is in
  `docs/verification/live_ollama_run_2026-10-14.log`.
- `tests/integration/test_postgresql_schema.py` (4), `tests/integration/test_postgresql_concurrency.py`
  (2) — need a PostgreSQL 16 database (`TEST_POSTGRES_*` variables) and are skipped at
  collection without one; CI runs them in the `postgres` job.

The executed accounting, including the static gates, is recorded in PROJECT_STATE.md (*Headline numbers*, measured 2026-10-14).

# Key Test Modules

| Test Module | Coverage |
|---|---|
| `tests/api/test_auth_routes.py` | Registration, login, profile (`/me`), logout, credential validation |
| `tests/api/test_auth_hardening.py` | Authenticated logout, persistent `jti` revocation, lockout and rate limits |
| `tests/api/test_admin_routes.py` | Admin user listing, role/status mutation, last-admin safeguards |
| `tests/api/test_report_export_api.py` | Text and PDF export endpoints |

| `tests/api/test_auth_dependencies.py` | Bearer token extraction, UserContext resolution, RBAC injection |
| `tests/api/test_openapi_contract.py` | Committed `openapi.json` diffed against the live schema; `/api` prefix rule |
| `tests/identity/test_token_service.py` | HMAC-SHA256 token issuance, claims validation, expiration |
| `tests/identity/test_password_hasher.py` | PBKDF2-HMAC-SHA256 hashing, salting, constant-time verification |

| `tests/frontend/` | Streamlit views, session state management, tenant cleanup, export buttons, and the AST boundary test (`test_frontend_boundaries.py`) |
